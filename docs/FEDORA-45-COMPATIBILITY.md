# Fedora 45 compatibility baseline

Feclora's target runtime baseline is Fedora Linux 45. Update system packages
through Fedora 45 repositories; do not substitute Rawhide or an arbitrary
upstream release for the system toolchain.

## Verified frontend baseline

| Component | Feclora pin | Fedora/Cockpit reference | Assessment |
|---|---:|---|---|
| Node.js | 22.23.1 | Fedora 45 stable `nodejs22` 22.23.1-4.fc45 | Aligned |
| npm | 10.9.8 | Fedora 45 `nodejs22-npm` 10.9.8-1.22.23.1.4.fc45 | Aligned |
| React | 18.3.1 | Cockpit 372 development dependencies | Aligned |
| React DOM | 18.3.1 | Cockpit 372 development dependencies | Aligned |
| PatternFly | 6.7.0 | Cockpit 372 development dependencies; Fedora 45 cockpit-files metadata | Aligned |
| Vite | 8.3.8 | Build-only npm dependency; not the Fedora runtime | Node engine compatibility checked |
| @vitejs/plugin-react | 6.3.0 | Build-only npm dependency; not the Fedora runtime | Node engine compatibility checked |

The React and PatternFly pins follow the upstream Cockpit 372 development
manifest, the relevant Cockpit baseline shipped by Fedora 45. Cockpit's
manifest pins React and React DOM to 18.3.1 and PatternFly packages to 6.7.0.
The Fedora 45 package metadata independently lists the PatternFly and React
bundles in Cockpit components.

Fedora 45 stable currently publishes Node.js 22.23.1 and npm 10.9.8. Vite 8
and the React Vite plugin require Node 20.19+ or 22.12+; Node 22.23.1 satisfies
that requirement. These two tools remain development dependencies and are
not installed as Feclora runtime packages.

## Build enforcement

- `webui/package.json` pins the Node.js, npm, React, React DOM and PatternFly
  baseline exactly.
- `webui/scripts/check-dependency-pins.mjs` checks those baseline versions.
- GitHub Actions uses Node.js 22.23.1 and npm 10.9.8 for frontend validation.

## Reproducible frontend installation

`webui/package-lock.json` is committed with lockfile format version 3 and
was generated by npm 10.9.8 from the exact frontend manifest. GitHub Actions
uses the same pinned Node.js/npm toolchain and runs `npm ci`, so the
transitive dependency graph is installed from the committed lockfile rather
than being resolved afresh on each build.
